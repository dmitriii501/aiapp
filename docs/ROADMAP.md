## M3 — Паритет с Claude Code / Codex
- [x] Чекпоинты и откат (файлы, записанные `Write`/`Edit`; выбор файлов в диалоге)
- [x] Plan mode с утверждением плана (`ExitPlanMode`) и todo-список (`TodoWrite`)
- [x] Сабагенты (`Task`: `explore` только читает, `general` с теми же инструментами; параллельный запуск и свои агенты из каталога — позже)
- [x] Хуки, скиллы, слэш-команды, память (хуки и память — только из пользовательских файлов; подсказки по `/` в поле ввода — позже)
- [x] Compaction (автоматически на 80% окна и по `/compact`; полный журнал сессии остаётся)
- [x] Web search / fetch (`WebFetch`, `WebSearch`: работает без ключа через страницу DuckDuckGo, при блокировке она на 10 минут откладывается; Brave Search API или свой SearXNG надёжнее и при сбое выручает DuckDuckGo)
- [x] Песочница (AppContainer) для `Shell`: файлы, сеть, память, отказ вместо обхода (`[sandbox]` в пользовательском конфиге; `git` внутри не запускается — устройство NUL AppContainer открыть не может)
- [x] Песочница **по умолчанию для воркеров роя** (`shell = "workers"`; `"off"` отключает, `"autonomous"` и `"always"` расширяют на свои сессии); переключатель в настройках
- [x] `git` для воркеров: инструмент `Git` только для чтения (status, diff, log, show, blame, ls-files, branch, rev-parse) с проверенным git-каталогом и списком разрешённых параметров; коммиты и слияние делает рой
- [x] Закрыта дыра «воркер подменяет `.git` в worktree»: подмена заставляла рой выполнить команду из чужого конфига вне песочницы; теперь все git-операции роя в worktree идут по каталогу, найденному из основного репозитория (тест воспроизводит атаку)
- [x] Закрыта дыра «junction в рабочей папке ведёт наружу»: проверка «внутри ли папки» идёт по настоящему пути (`RealPath`), для разрешений на чтение, записи, ограничения воркеров и записей в песочнице
- [x] Права контейнера на папки снимаются при выходе и у CLI (раньше только у приложения)
- [x] `kairo sandbox check`: что запускается внутри песочницы на этом ПК, какие папки добавить в `read`, что требует одноразовой команды администратора (инструменты в Program Files)
- [ ] Песочница: запасные варианты (Windows Sandbox, WSL) и сеть по списку адресов вместо «всё или ничего»

- [ ] Игровая часть политик: экстракторы (OCR, шаблоны, пиксели), захват кадров, пересмотр политики по логам, каталог политик
- [x] Генерация кандидатов, ворота уверенности, эскалация, проверка после шага (`PcPursue`: один запрос к Jev на шаг, ~0,3 с)

- [x] Режимы автономности: `[pc] autonomous` (без вопросов в «Без подтверждений»), `[pc] all_apps` (любые программы, кроме терминалов, менеджеров паролей, системных инструментов, редакторов кода и самого Kairo; запуск вне списка только для оконных программ)
- [x] Стабильные id элементов между просмотрами; в окнах больше 40 элементов `PcAct` возвращает только изменения (контекст большой модели заполняется медленнее)
- [x] Лимита на число шагов быстрого цикла и политик по умолчанию нет (`[pc] max_steps`, `max_steps` у `PcPursue` и политик задают потолок, если он нужен); остановки: цель достигнута, быстрая модель передала шаг, ничего не меняется, «хожу по кругу», клавиша Pause, отмена, у политики — лимит времени
- [x] Зрение через Jev 1.14: `PcSee` (где это на картинке / верно ли то, один запрос с вопросами box и да/нет, второй взгляд на увеличенный кусок для мелких целей) и `PcClick` (клик по описанию словами); картинки окон уходят в Jev только по флажку `[pc] jev_vision`; гайд `/game`; `kairo jev models|box|boxeval`
- [x] Для 0.1.5: `/goal` (цель: агент не останавливается, пока не вызовет `GoalComplete` с доказательством или `GoalBlocked`; сбой ответа модели повторяется с паузой, два хода подряд без действий и остановка пользователем ставят цель на паузу, `/goal resume` и `/goal clear`; цель хранится в сессии и после перезапуска возвращается на паузе), основной цикл агента без предела в 60 вызовов модели за ход (внезапные остановки на длинных задачах), `kairo models list|bench`, исправление обновления (программы, запущенные Kairo, больше не держат папку установки)
- [x] Для 0.1.4: `right_click_at` (контекстные меню), `drag_path` с `shape=ellipse|rectangle` и `smooth` (фигура одним вызовом), `PcBatch` (несколько действий за один вызов), `PcClipboard` (текст и картинки через буфер; чтение всегда спрашивает), инструмент `Download` (картинки, PDF, данные; программы и скрипты не сохраняются), понятное сообщение при ошибке 451 у Jev, ошибки и отмены ходов в истории сессии и разброс времени ходов модели в `kairo sessions timeline`, список по `/` в поле ввода: инструменты `/pc`, `/draw`, `/browser`, команды и скиллы

- [x] Ожидание реакции экрана: короткая пауза после действия и повторные просмотры вместо фиксированной паузы (действие 141 → 45–60 мс); ожидание смены картинки после клика по координатам

- [x] `PcCheck` отличает «нет» от «по списку элементов не определить» (второй вопрос в том же запросе)
- [x] Сообщения сессий хранятся со временем; `kairo sessions timeline [id]` показывает, куда ушло время: модель, инструменты (с ожиданием ответа на вопрос), пользователь. База старой версии обновляется сама, старые сообщения остаются без времени
