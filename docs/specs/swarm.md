# Спецификация: рой агентов (черновик v0)

## Идея

Запустить много агентов параллельно над одной большой задачей. У каждого своя роль, модель и изолированное рабочее пространство. Координация идёт через общую доску задач и сообщения. Пользователь видит всё в реальном времени и может вмешаться в любой момент.

**Чем рой отличается от сабагентов:**

| | Сабагент | Рой |
|---|---|---|
| Модель работы | вызов функции: «сходи и вернись с ответом» | долгоживущие агенты, работают параллельно |
| Время жизни | внутри одного хода родителя | минуты и часы, в фоне, переживает перезапуск |
| Общение | только итог родителю | друг с другом: сообщения, доска, общая память |
| Файлы | общие с родителем | своё рабочее пространство (git worktree) |

## Сценарии

- **Большая фича или рефакторинг.** Лид разбивает задачу, 3–5 разработчиков работают в своих worktree, ревьюер проверяет, лид сливает.
- **Best-of-N.** Три агента на разных моделях решают одну задачу, судья (или пользователь) выбирает лучшее решение.
- **Конвейер.** Аналитик → архитектор → разработчик → тестировщик → ревьюер.
- **Исследование.** N агентов копают разные источники, один пишет итоговый отчёт.
- **Не только код.** Параллельная обработка сотен файлов и документов, массовые правки.

## Топологии

| Топология | Как работает | Приоритет |
|---|---|---|
| `orchestrator` | Лид планирует, порождает воркеров, раздаёт задачи, собирает результат | P1, по умолчанию |
| `pipeline` | Задача проходит по ролям последовательно, этапы могут параллелиться по подзадачам | P2 |
| `best-of-n` | N независимых попыток + судья | P2 |
| `board` | Нет лида: агенты сами берут задачи с доски и создают новые | P2 |

## Примитивы

- **Агент роя** — роль, модель, инструменты, разрешения, рабочее пространство, бюджет. Внутри — обычный agent loop из `Kairo.Core`.
- **Доска задач** — задачи с зависимостями (DAG). Статусы: `pending → claimed → in_progress → review → done | failed`. У задачи есть исполнитель и артефакты. Взятие задачи (`claim`) атомарное.
- **Шина сообщений** — личные сообщения и broadcast. Доставляются в начале следующего хода получателя.
- **Общая память (blackboard)** — заметки и артефакты, видимые всему рою.
- **Рабочие пространства:**
  - `git-worktree` — у каждого агента своя ветка и папка (по умолчанию для кода);
  - `shared` — общая папка с блокировкой файлов;
  - `readonly` — только чтение (исследование, ревью).
- **Слияние** — лид или отдельный merge-агент сливает ветки и разбирает конфликты. Итог — сводный дифф на ревью пользователю.

## Инструменты, доступные агентам роя

| Инструмент | Кому |
|---|---|
| `task_list`, `task_claim`, `task_update` | всем |
| `task_create` | лиду; в топологии `board` — всем |
| `send_message`, `read_inbox` | всем |
| `memory_read`, `memory_write` | всем |
| `spawn_agent`, `stop_agent` | лиду, в рамках `can_spawn` и лимитов |
| `swarm_finish` | лиду |

## Описание роя: `swarm.toml`

Рои публикуются в каталоге наравне с агентами.

```toml
id       = "com.kairo.feature-team"
name     = "Feature team"
version  = "0.1.0"
topology = "orchestrator"

[limits]
max_agents      = 6
max_depth       = 1          # могут ли воркеры порождать своих агентов
max_cost_usd    = 5.00
max_duration    = "2h"
max_concurrency = 4          # одновременных запросов к моделям

[workspace]
mode = "git-worktree"        # git-worktree | shared | readonly

[[roles]]
id        = "lead"
agent     = "builtin:planner"          # встроенный агент или id из каталога
model     = "claude-opus-*"
count     = 1
can_spawn = ["coder", "reviewer"]

[[roles]]
id    = "coder"
agent = "builtin:coder"
model = "claude-sonnet-*"
count = "1..4"                         # сколько именно — решает лид

[[roles]]
id    = "reviewer"
agent = "com.example.pr-reviewer"
model = "gpt-5*"
count = 1
```

Модели можно смешивать: сильная для лида, быстрые и дешёвые (или локальные) для воркеров.

## Исполнение

- **Планировщик.** Общая очередь запросов к моделям с лимитами на провайдера и ключ (RPM, TPM, параллельность). Приоритеты: лид > ревьюер > воркеры.
- **Состояние.** Доска, сообщения, память и сессии всех агентов лежат в SQLite. Рой можно поставить на паузу, продолжить, он переживает перезапуск приложения.
- **Фон.** При закрытом окне рой продолжает работать: десктоп сворачивается в трей. Позже — отдельный фоновый процесс (см. [ARCHITECTURE](../ARCHITECTURE.md#принципы)).
- **Завершение.** Лид вызывает `swarm_finish` → итоговый отчёт + сводный дифф → ревью пользователя → слияние в основную ветку.

## Безопасность

- **Разрешения сужаются по иерархии:** пользователь ⊇ рой ⊇ роль ⊇ агент. Никто не может выдать другому больше, чем имеет сам.
- **Единая очередь подтверждений.** Запросы разрешений от всех агентов попадают в один inbox и группируются: «4 агента хотят запустить `npm test`» → одобрить для всех.
- **Сообщения между агентами — данные, а не инструкции пользователя.** Метка недоверия (taint) распространяется: если агент читал веб или вывод MCP, его сообщения тоже помечены.
- **Автономный рой** (без подтверждений) работает только в песочнице.
- **Жёсткие бюджеты.** При достижении лимита рой ставится на паузу и спрашивает пользователя.
- **Kill switch.** Остановить одного агента или весь рой — одной кнопкой и глобальной горячей клавишей.

## UI

- **Карта роя:** агенты — узлы графа, рёбра — сообщения и зависимости задач. Живые анимации состояний: думает, вызывает инструмент, ждёт разрешения, готово, ошибка.
- **Доска задач** (канбан).
- **Лента сообщений** между агентами.
- **Транскрипт любого агента** по клику; можно написать конкретному агенту напрямую.
- **Бюджет:** токены, деньги, время — в реальном времени.
- **Управление:** пауза, стоп, перезапуск отдельного агента или всего роя.

## Приоритеты

- **P1:** топология `orchestrator`, git worktrees, доска задач, сообщения, бюджеты, единая очередь подтверждений, карта роя, пауза и продолжение.
- **P2:** `pipeline`, `best-of-n`, `board`, рои в каталоге, фоновый процесс, удалённое наблюдение с телефона.

## Открытые вопросы

- Изучить существующие подходы (agent teams в Claude Code, handoffs в OpenAI Agents SDK, CrewAI, AutoGen) и взять лучшее.
- Как делить один API-ключ на 10 агентов, не упираясь в rate limits. Возможно, ротация ключей и разные провайдеры для разных ролей.
- Разумные лимиты по умолчанию, чтобы пользователь случайно не сжёг $50.
- Как показывать 10+ одновременных стримов, не перегружая UI и пользователя.
