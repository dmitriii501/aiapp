# Модель безопасности

Агент с доступом к shell, файлам и управлению ПК — это потенциально очень опасная программа. Безопасность — не фича, а фундамент: её нельзя «добавить потом».

## Угрозы

1. **Ошибка модели** — агент удаляет не те файлы, делает `git push --force`, закрывает несохранённый документ.
2. **Prompt injection** — вредные инструкции в веб-странице, файле, ответе MCP-сервера, тексте на экране.
3. **Вредоносный агент или MCP-сервер из каталога.**
4. **Утечка секретов** — ключи в логах, в контексте модели, в отправке на сторонний сервер.

## Уровни риска инструментов

| Уровень | Примеры | По умолчанию |
|---|---|---|
| `read` | Read, Glob, Grep, список окон, скриншот | разрешено в пределах проекта |
| `write` | Write, Edit | спросить (или авто-разрешение в режиме «принимать правки») |
| `exec` | shell, запуск приложений, MCP-инструменты | спросить |
| `system` | мышь/клавиатура, UI Automation, завершение процессов, вне папки проекта | спросить, всегда показывать |
| `network` | web fetch, загрузка файлов | спросить для новых доменов |

## Правила разрешений

Как в Claude Code — списки `allow` / `ask` / `deny` с шаблонами, на уровне пользователя и проекта. `deny` всегда сильнее `allow`.

```toml
[permissions]
allow = ["Read", "Bash(git status)", "Bash(npm test:*)"]
ask   = ["Bash(git push:*)"]
deny  = ["Read(**/.env)", "Bash(rm -rf:*)", "PC(app:Banking*)"]
```

Режимы сессии: **По умолчанию** · **Принимать правки** · **Plan (только чтение)** · **Автономный** (только внутри песочницы).

## Защита от prompt injection

- Всё, что пришло из инструментов, помечается как **данные**, не инструкции — и в промпте, и в UI.
- Результаты web/MCP/экрана не могут поднять уровень доверия сессии.
- Опасные действия после чтения недоверенного контента требуют подтверждения даже при правиле `allow` (taint tracking — P1).

## Мост UI ↔ ядро

Интерфейс — веб-страница в WebView2, и он рендерит текст от модели. Значит, интерфейс считаем **потенциально скомпрометированным** и не даём ему полномочий.

- Мост — только JSON-RPC через `PostWebMessageAsJson` / `WebMessageReceived`. `AddHostObjectToScript` не используется.
- Методы — намерения пользователя, а не команды. Методов вида «выполни команду» или «запиши файл» в протоколе нет. Ответ на запрос разрешения ядро принимает только для реально ожидающего запроса.
- Белый список методов, проверка origin (`https://app.kairo.local`) у каждого сообщения.
- Markdown от модели проходит через санитайзер, сырой HTML запрещён, CSP `script-src 'self'`. Mermaid и SVG — в sandbox-iframe.
- Навигация за пределы приложения и открытие новых окон блокируются. Ссылки открываются во внешнем браузере после подтверждения.

Даже при XSS в интерфейсе атакующий может максимум нажать «разрешить» на уже показанный запрос — и то это видно пользователю. Для `system`-действий подтверждение дополнительно идёт через нативный диалог оболочки (P1).

## Рой агентов

Подробно — в [спецификации роя](specs/swarm.md#безопасность). Коротко:

- Разрешения только сужаются: пользователь ⊇ рой ⊇ роль ⊇ агент.
- Сообщения между агентами — данные, а не инструкции пользователя. Метка недоверия передаётся по цепочке сообщений.
- Автономный рой — только в песочнице.
- Жёсткие бюджеты (токены, деньги, время) и kill switch по горячей клавише.

## Песочница

- **P1:** shell-команды в автономном режиме — в AppContainer (запасные варианты — Windows Sandbox / WSL) с доступом только к папке проекта.
- Каждый запущенный процесс — в Job Object: лимиты CPU и памяти, гарантированное завершение всего дерева процессов при отмене.
- Сеть в песочнице по умолчанию выключена или ограничена списком доменов.

## Чекпоинты

Каждая запись файла инструментами `Write` и `Edit` идёт после снимка: перед первым изменением файла в запросе сохраняется его прежнее содержимое (или факт, что файла не было). Под каждым запросом, который что-то менял, есть кнопка «Откатить…»: в диалоге видно каждый файл, что с ним будет и разницу, и можно выбрать, какие файлы откатывать. Это главная страховка от ошибок модели.

- **Что не покрыто.** Действия команд (`Shell`), MCP-инструментов и всё, что агент сделал вне `Write`/`Edit`, не откатывается. Это сказано в самом диалоге.
- **Чужие изменения не затираются молча.** Если файл изменили после агента (вы сами или команда), он помечается «Файл изменили после агента» и по умолчанию не выбран; перезапись возможна только явным выбором.
- **Интерфейс выбирает только из записанного.** Путь, которого нет в чекпоинте, игнорируется: откат не может записать или удалить произвольный файл.
- **Откат запрещён, пока агент работает** в этой сессии. После отката модель получает пометку и должна заново прочитать файлы перед правкой.
- Файлы больше 2 МБ не сохраняются; откат такого файла помечается недоступным.

## Терминал

Встроенный терминал — единственное место, где ввод из интерфейса попадает в оболочку, поэтому у него жёсткие рамки:

- Это ввод самого пользователя. Агент не может писать в терминал: у него есть свой инструмент `Shell` с разрешениями и правилами.
- Программу выбирает хост (PowerShell 7 или Windows PowerShell). Интерфейс присылает только нажатия клавиш и размер окна, команду запуска задать нельзя.
- Папка должна быть известной рабочей папкой (выбранной через системный диалог). Терминалов не больше 8, вставка за один раз не больше 64 КБ.
- Оболочка и всё, что она запустила, лежат в Job Object с `KILL_ON_JOB_CLOSE`: закрытие вкладки, окна или падение Kairo не оставляет процессов.
- Терминал не вносит в разрешения агента ничего: правила и режимы сессии на него не влияют, и наоборот.

## MCP-серверы

- Сервер — чужой код с правами пользователя. Конфиг `mcp.json` меняется только действием пользователя в интерфейсе или вручную; агент не может добавить сервер.
- Конфигурации из репозиториев (`.mcp.json`) не читаются, чтобы открытие проекта не запускало процессы.
- Все вызовы MCP-инструментов — риск `exec`: по умолчанию спрашиваем. Подсказки сервера (`readOnlyHint` и подобные) в расчёт не берутся. Разрешить сервер целиком можно правилом `mcp__server__*`.
- Ответы серверов — данные, а не инструкции (см. «Prompt injection» выше): они не меняют режим и разрешения сессии.

## Агенты и MCP из каталога

- Манифест явно декларирует нужные инструменты и разрешения — пользователь видит их перед установкой.
- Агент не может выдать себе разрешения сверх декларированных.
- Обновление, расширяющее разрешения, требует повторного подтверждения.
- Реестр модерируется через PR; закрепляем версии по хэшу коммита.

## Секреты

- Ключи — только в Windows Credential Manager.
- Маскирование известных секретов в логах и в контексте модели.
- Никакой телеметрии по умолчанию. Если появится — opt-in и без содержимого сессий.
