# ADR-0002: Двухуровневое управление ПК (System 1 + System 2)

- **Статус:** предложено
- **Дата:** 2026-10-13

## Контекст

Классический computer use — большая модель смотрит на скриншот и решает каждый клик. Это 2–10 секунд и заметные деньги на шаг. Для задач на десятки шагов это слишком медленно, и пользователь просто сделает всё руками быстрее.

В 2026 году появились модели решений класса «System One» (первая — Jev от TypeSafe AI): они не генерируют текст, а выбирают вариант из списка с вероятностями и уверенностью за 70–500 мс. Windows через UI Automation отдаёт структуру любого окна в виде текста — ровно тот вход, который им нужен.

## Решение

Управление ПК строим в два уровня — подробно в [спецификации](../specs/pc-control.md):
- **System 2** (обычная LLM) строит план, готовит тексты для ввода и разбирает сложные случаи.
- **System 1** (модель решений) на каждом шаге выбирает действие из отфильтрованных кандидатов и проверяет результат.
- Переход от System 1 к System 2 — по порогу уверенности, риску действия и отсутствию прогресса.
- Основной источник наблюдения — дерево UI Automation, скриншоты — только при эскалации.
- Ядро зависит от интерфейса `IDecisionModel`, а не от конкретного вендора. Jev — первый адаптер, плюс запасной адаптер на любой быстрой LLM.

## Последствия

- (+) Шаги на порядок быстрее и дешевле, большие задачи становятся практичными.
- (+) Предсказуемость: System 1 выбирает только из списка, который сформировало и проверило ядро.
- (+) Та же абстракция пригодится для маршрутизации моделей, роя и оценки риска.
- (−) Зависимость от молодого продукта в раннем доступе. Смягчаем абстракцией и режимом «только System 2».
- (−) Приложения без UIA-дерева не ускоряются.
- (−) Качество на русскоязычном UI неизвестно — нужен отдельный eval до того, как делать System 1 режимом по умолчанию.
