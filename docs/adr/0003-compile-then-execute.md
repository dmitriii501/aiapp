# ADR-0003: Принцип «LLM компилирует — System 1 исполняет»

- **Статус:** принято
- **Дата:** 2026-10-13

## Контекст

[ADR-0002](0002-pc-control-system1-system2.md) ввёл связку LLM + модель решений для управления ПК. Та же схема подходит для игр, повторяющихся задач и, возможно, роя. Нужен общий принцип, а не отдельные решения под каждый случай.

## Решение

Для задач из множества однотипных решений:
1. **LLM компилирует** задачу в **политику** — декларативный JSON: восприятие (как получить текстовое состояние), действия, рефлексы, вопросы к модели решений, проверки, правила эскалации.
2. **Рантайм политик** (`Kairo.Policy`) исполняет её в цикле: рефлексы → System 1 → ворота уверенности → действие → лог.
3. **LLM возвращается** при эскалации и периодически пересматривает политику по логам.

Формат и пример — в [спецификации](../specs/decision-policy.md).

## Ключевые правила

- Политика — данные, а не код: только экстракторы, действия и выражения из библиотеки Kairo.
- Восприятие в цикле быстрое и локальное (API игры, OCR Windows, шаблоны, пиксели). VLM в цикле не используется.
- Три уровня скорости: рефлексы (без модели) → System 1 → System 2.
- Ввод только в целевое окно; лимиты и kill switch обязательны.
- Никакого обхода античитов и чтения памяти защищённых процессов.

## Последствия

- (+) Длинные задачи из тысяч шагов становятся быстрыми и дешёвыми.
- (+) Политики переиспользуются и ими можно делиться.
- (+) Решения System 1 логируются с вероятностями — видно, где политика слабая.
- (−) Качество целиком зависит от восприятия; для игр без API разметка экрана — самая хрупкая часть.
- (−) Реакционные игры остаются за пределами подхода.
- (−) Новый формат, который придётся поддерживать и версионировать.
