# ADR-0005: Установщик и автообновления — Velopack

**Статус:** принято

## Контекст

Нужны установщик и автообновление для приложения WinUI 3 без пакета (self-contained Windows App SDK, ~240 МБ), которое распространяется как открытый проект через GitHub. Варианты: Velopack и MSIX.

## Решение

Velopack.

- **Без сертификата можно выпускать.** MSIX требует подписи доверенным сертификатом, иначе пакет не ставится. Velopack-установщик запускается без подписи (Windows покажет предупреждение SmartScreen); подпись добавляется позже одним параметром `vpk pack`.
- **Подходит к нашей сборке.** Мы уже отказались от MSIX в пользу unpackaged self-contained (ADR-0001). Velopack пакует папку публикации как есть.
- **Установка без прав администратора**, в профиль пользователя; обновление тихое.
- **Дельта-обновления:** между версиями качается только разница.
- **Источник — GitHub Releases.** Отдельный сервер не нужен.
- Есть портативный архив и MSI для организаций (`--msi`).

Минусы: два установщика (Setup.exe и MSI) требуют внимания к подписи; нет магазина Microsoft Store. Магазин не нужен до 1.0, а MSIX можно добавить позже рядом.

## Как это устроено

- **Точка входа** `src/Kairo.Desktop/Program.cs` своя, а не сгенерированная XAML: `VelopackApp.Build().Run()` обязан выполниться первым (установщик запускает приложение с особыми аргументами и ждёт быстрого выхода).
- **`IAppUpdater`** в `Kairo.Host` скрывает Velopack; `UpdateService` отвечает за состояние (`disabled`, `idle`, `checking`, `available`, `downloading`, `error`), периодическую проверку (через 30 с после запуска и раз в 6 часов; отключается `[update] check = false`) и установку.
- **Ставим только по просьбе пользователя** и не тогда, когда работает агент. Загрузка идёт по кнопке «Установить и перезапустить».
- **Адрес обновлений нельзя подменить из проекта.** Источник: переменная `KAIRO_UPDATE_URL`, затем пользовательский `config.toml` (`[update] url`), затем адрес, вшитый при сборке релиза (`-p:KairoUpdateUrl`). Проектный `.kairo/config.toml` не читается: иначе репозиторий мог бы подменить само приложение. Из интерфейса адрес тоже не задаётся.
- Сборка из репозитория (не из установщика) обновляться не может: в интерфейсе состояние `disabled`.

## Автоматическая установка

Найденная версия по умолчанию скачивается сама (`[update] auto_install`, только из пользовательского файла) и **ставится при закрытии Kairo**: следующий запуск уже новый. Сам Kairo не перезапускается ни при каких условиях: «Перезапустить и обновить» — только по кнопке и не при работающем агенте. Тот же выключатель `[update] check = false` отключает и проверку, и загрузку.

## Доверие к обновлениям

Пока пакеты не подписаны, доверие держится на HTTPS и на контроле над репозиторием на GitHub: Velopack сверяет хэши пакетов с лентой релизов, но не проверяет автора. Автоматическая загрузка делает это доверие важнее: компрометация аккаунта или тега `v*` доходит до всех установленных копий без единого клика пользователя. До публичной alpha: сертификат или Azure Trusted Signing, двухфакторная защита аккаунта и защита тегов `v*`.
