# ADR-0001: Технологический стек

- **Статус:** принято; оформление уточнено в [ADR-0004](0004-editor-style-ui.md) (без Mica и выразительных анимаций)
- **Дата:** 2026-10-13

## Контекст

Нужен Windows-апп, который:
- имеет глубокий доступ к Windows API (UI Automation, ввод, окна, Credential Manager, ConPTY, AppContainer);
- показывает богатый контент: стриминг Markdown с кодом и таблицами, редактор кода, диффы, терминал, живую карту роя агентов;
- выглядит красиво и уникально, с плавными анимациями;
- использует тот же движок в CLI;
- держит десятки параллельных агентов (рой);
- понятен контрибьюторам open source.

## Рассмотренные варианты

| | **.NET + WebView2** (выбрано) | Нативный WinUI 3 | Tauri 2 + Rust | Electron |
|---|---|---|---|---|
| Доступ к Windows API | отличный (CsWin32, FlaUI, WinRT) | отличный | хороший (`windows-rs`), но многое писать вручную | через нативные аддоны |
| Библиотеки ИИ и MCP | официальные SDK: MCP, OpenAI, Anthropic; `Microsoft.Extensions.AI` | те же | MCP есть, адаптеры моделей писать самим | официальные TS SDK |
| Чат с Markdown, Monaco, терминал | веб — всё готово | слабо, редактор и терминал всё равно через WebView | веб | веб |
| Уникальный дизайн и анимации | CSS / Motion / WebGL | Composition — плавно, но в рамках Fluent | веб | веб |
| Память | +100–200 МБ на WebView2 | минимальная | +WebView2 | наибольшая |
| CLI одним exe | Native AOT | Native AOT | да | нужен Node runtime |
| Порог входа | C# + TS — массовые языки | C# + XAML, XAML-разработчиков мало | Rust — высокий | только TS |
| Перенос на другие ОС в будущем | ядро и UI переносимы, оболочка — нет | нет | да | да |

## Решение

- **Ядро и всё системное — C# / .NET 10 (LTS).**
- **Оболочка — WinUI 3 (Windows App SDK):** окно, Mica, свой заголовок, трей, глобальные горячие клавиши, перетаскивание из Проводника, уведомления.
- **Интерфейс — React + TypeScript в одном WebView2 на всё окно** с прозрачным фоном, чтобы Mica просвечивала.
- **Связь UI ↔ ядро — JSON-RPC 2.0** поверх сообщений WebView2. Протокол не зависит от транспорта: позже тот же протокол пойдёт через named pipe / WebSocket для фонового процесса и удалённого UI.
- **CLI — `kairo.exe` на Native AOT** поверх того же ядра.

### Почему не полностью нативный WinUI 3

Около 70% экрана — чат с Markdown, код, диффы и терминал, и веб делает это лучше всего. В нативном варианте Monaco и терминал всё равно пришлось бы встраивать через WebView. Получилось бы две системы UI вместо одной.

### Почему не Tauri + Rust

Мы делаем только Windows, поэтому главный плюс Tauri — кроссплатформенность — не так важен. Зато на .NET есть официальные SDK для MCP и моделей, FlaUI для UI Automation, а порог входа ниже.

### Почему не Electron

Вес и память, Node runtime для CLI, Windows API только через нативные аддоны.

## Обязательные правила

Без них гибридная архитектура опасна или ощущается как сайт. Подробности в [ARCHITECTURE](../ARCHITECTURE.md#мост-ui--ядро) и [SECURITY-MODEL](../SECURITY-MODEL.md#мост-ui--ядро).

1. **Оболочка нативная.** Всё, что касается окна и ОС, делает WinUI 3, а не веб.
2. **У интерфейса нет полномочий.** Мост минимальный: UI шлёт намерения («ответить на запрос разрешения #42»), а не команды («выполни `rm`»). Markdown от модели проходит через санитайзер, строгий CSP, никакого сырого HTML.
3. **Бюджет на нативное ощущение.** Segoe UI Variable, системный акцентный цвет, родная прокрутка, учёт системной настройки «эффекты анимации», виртуализация списков, 60+ FPS при стриминге.

## Последствия

- (+) Лучший инструмент для каждой части: .NET для системы и ИИ, веб для контента.
- (+) CLI, десктоп и будущий фоновый процесс используют одно ядро и один протокол.
- (+) Интерфейс потом можно открыть в браузере или на телефоне для удалённого управления агентами.
- (−) Два языка и мост. Смягчаем: единый источник типов в `Kairo.Protocol`, TS-типы генерируются при сборке.
- (−) WebView2 добавляет 100–200 МБ памяти. Смягчаем: один экземпляр WebView2, ленивая загрузка Monaco и xterm.js.
- (−) Риск XSS через вывод модели. Смягчаем правилом 2.
- (−) Native AOT и COM (UI Automation через FlaUI) могут конфликтовать. Проверяем в M0: если не выйдет, CLI собирается без AOT или без модуля управления ПК.

## Результаты проб M0 (2026-10-13)

- **Гибрид работает.** Окно WinUI 3 + Mica + WebView2 с `DefaultBackgroundColor="Transparent"`: Mica просвечивает сквозь UI. Важная деталь: `color-scheme` нужно ставить на `body`, а не на `:root` — иначе Chromium заливает холст непрозрачным цветом.
- **Мост работает.** JSON-RPC через `PostWebMessageAsJson` / `WebMessageReceived` с проверкой origin; `app.info` и потоковый `echo.stream` проходят в настоящем WebView2.
- **Native AOT для CLI пока откладываем.** Официальный Anthropic C# SDK (12.55) использует reflection-based JSON: анализ тримминга дал ~270 предупреждений IL2026, под AOT он может ломаться во время выполнения. Наши проекты (`Protocol`, `Core`, `Providers`) при этом чистые. Сейчас CLI — обычный single-file (нужен .NET runtime). Кроме того, для AOT на машине разработчика нужен линкер MSVC (Visual Studio Build Tools, «Desktop development with C++»). Варианты — в [OPEN-QUESTIONS](../OPEN-QUESTIONS.md).
- (−) Оболочка и `Kairo.Windows` привязаны к Windows. Это осознанно, см. [VISION](../VISION.md).
